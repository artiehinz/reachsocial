DEVELOPER DOCUMENTATION

Call the API.

Choose an available API and send a public URL. For public paid calls, use an x402-compatible client with USDC on the stated network. No ReachSocial signup or API key is required. Generated machine documentation is available in OpenAPI, llms.txt, and the agent guide.

Check the available APIs

curl https://reachsocial.dev/v1/services

This discovery request is free. To set up an agent, share https://reachsocial.dev/agent.md and ask it to configure a compatible wallet and a spending limit before paying.

Get a payment quote

REQUEST_KEY="$(python3 -c 'import uuid; print(uuid.uuid4())')"
curl -i https://reachsocial.dev/v1/services/instagram.profile/execute \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $REQUEST_KEY" \
  --data '{"input":{"url":"https://www.instagram.com/example/"}}'

This unsigned request does not pay. An available route returns HTTP 402 with payment details. Your x402 client validates those details and sends the payment authorization using the same request key and body. Keep the key for recovery; generate a new one for a different request.

Approved API-key clients

Private integrations and MCP require approved access. API-key REST requests use Authorization: Bearer <your-api-key> and the same input body; they bypass x402 under the client's billing agreement.

Background jobs (currently on hold)

No background-job service is currently public. For an already accepted job, retain the job_token received at submission and poll GET /v1/jobs/{job_id} with X-Job-Token. Paid anonymous jobs are retained for 30 days so a lost response can be recovered.

Do not repeat a paid job submission while work is pending. Poll the returned status URL until a terminal state.

Handling errors

Errors contain a stable code, safe message, retryable flag, and request ID. Invalid input, unavailable private content, and not-found results are terminal.

{"error":{"code":"not_found",
 "message":"The resource was not found.",
 "retryable":false,
 "request_id":"req_..."}}

Paying through x402

Public available services require a random Idempotency-Key of 32 to 255 characters (for example, a fresh UUID) and return 402 Payment Required with a PAYMENT-REQUIRED header. An x402-compatible buyer verifies the exact amount, receiver, network, asset, and resource, signs the requirement, and retries once with PAYMENT-SIGNATURE. {{ payment_network }} is the current public payment network; B2B Bearer calls bypass x402.

If a paid response is lost, repeat the same request with its original key and input or call POST /v1/payments/recover/{service_id}; ReachSocial returns the stored result or job without another transfer or provider execution during the 30-day paid-result retention window. Keep the key private: it grants access to that result when paired with the original input. If an accepted paid job later fails because ReachSocial or its provider is unavailable, claim one replacement credit at POST /v1/jobs/{job_id}/credit. Present it once as X-Service-Credit for the same service. Never send a B2B API key or wallet private key to a browser or service input.
