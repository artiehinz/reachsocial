DEVELOPER DOCUMENTATION

Integrate one paid request.

Use one browser wallet and one tested TypeScript helper. ReachSocial checks the public URL before settlement, returns normalized JSON, and keeps the result recoverable for 30 days.

THREE STEPS

From setup to response.

  1. 1
    Install the x402 client

    Add the official packages below and copy the helper.

  2. 2
    Connect your browser wallet

    Pass its provider and selected address to the helper.

  3. 3
    Call and keep the key

    Each payment needs approval. Store the returned idempotency key for recovery.

BROWSER TYPESCRIPT

Copy the working client.

Install the official x402 packages:

npm install @x402/core@2.28.0 @x402/evm@2.28.0 @x402/fetch@2.28.0

The helper accepts only x402 v2, Base mainnet, native USDC, the receiver published by ReachSocial, the exact request URL, and at most $0.05. It asks the wallet to approve every paid request.

Show TypeScript helper
{{ browser_example }}

Call it with an injected wallet provider:

const provider = (window as Window & { ethereum: BrowserProvider }).ethereum;\nconst account = await connectBrowserWallet(provider);\nconst input = { url: "https://www.instagram.com/instagram/" };
const paid = await executeReachSocial(provider, account, "instagram.profile", input);

// Save paid.idempotencyKey beside your own request record.
console.log(paid.result);

// If the paid response was lost, recovery uses ordinary fetch and never signs again.
const recovered = await recoverReachSocial(
  "instagram.profile", input, paid.idempotencyKey
);

Request input

POST /v1/services/instagram.profile/execute
Content-Type: application/json
Idempotency-Key: 5d714f31-41f6-4bbb-a692-f54e0a2babdc

{"input":{"url":"https://www.instagram.com/instagram/"}}

The idempotency key must be random and 32–255 characters. Reuse it only for the exact same service and input.

SAFE RETRIES

Keep the request key.

A fresh key identifies one intended purchase. A retry with the same key and input returns the stored result instead of charging or calling the provider again. If the response was lost, call POST /v1/payments/recover/{service_id} with that original key and input. The TypeScript helper’s recoverReachSocial method uses ordinary fetch, so recovery cannot request a wallet signature.

Keep the key private while the result is retained: the key and original input grant access to that result.

The guide cannot access a wallet or approve spending by itself.
