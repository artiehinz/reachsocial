Import loadInstagramProfile in your app and call it from a button handler. It connects your installed wallet, requests approval for one payment, and returns the result. If your app already selects a wallet, pass that provider to the helper instead.

This example retains the request key in this browser tab. In your application, save the key and original input with your request record before payment.

Native Base-USDC contract: 0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913. Verify the network and token in your wallet before sending.

Lost the response? Recover it.

Use recoverInstagramProfile() from the example, or call recoverReachSocial(service, originalInput, originalKey). Recovery returns the stored result and payment state for 30 days. It never asks for another signature or provider request.

A request key identifies one purchase. Keep it private and reuse it only with the exact same service and input. A fresh key starts a new purchase.

Errors and uncertain outcomes

ReachSocialRequestError.idempotencyKey retains the key after a failed execution response. Keep the key even if the request times out. A failed recovery or HTTP 404 does not prove that no payment occurred; check again or contact support before starting a fresh purchase.

HTTP 429 means a request limit was reached. HTTP 503 means the service or payment path is temporarily unavailable. Use service status and the original recovery key; do not automatically create another payment.

API-key clients and background jobs

Approved API-key and MCP integrations belong on your server. Bearer keys, job tokens, and replacement credits are not supported by this public browser helper. Existing accepted jobs retain their protected polling and recovery routes. See OpenAPI for those contracts.

Your agent needs HTTP tools and a compatible wallet integration.
